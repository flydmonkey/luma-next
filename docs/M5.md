# M5：麦克风混音与窗口捕获

M5 在同一个 libobs 进程和 session 数据源中增加 `wasapi_input_capture` 与
`window_capture`。不使用 obs-websocket，也不改变托盘与浏览器宿主边界。

## API

```powershell
curl.exe http://127.0.0.1:18765/api/v1/targets
curl.exe http://127.0.0.1:18765/api/v1/devices/audio

curl.exe -X POST -H "Content-Type: application/json" `
  -d '{"mode":"display","system_audio":true,"microphone":true,"mic_device_id":"default"}' `
  http://127.0.0.1:18765/api/v1/session/start

# window_id 必须原样来自 /targets；任意或过期值会被拒绝
curl.exe -X POST -H "Content-Type: application/json" `
  -d '{"mode":"window","window_id":"<enumerated-id>","system_audio":true,"microphone":false}' `
  http://127.0.0.1:18765/api/v1/session/start
```

settings 新增 `capture_mode`、`display_id`、`window_id`、`mic_device_id`，并继续使用
`record_system_audio` 与 `record_microphone`。系统声与麦克风至少启用一个；两者都关闭
会在创建 OBS 输出前返回 422。session 明文返回模式、目标摘要、两个开关、实际活动的
音频源以及窗口捕获警告。

## 行为

- 系统声使用 `wasapi_output_capture`，麦克风使用 `wasapi_input_capture`，共同进入 OBS
  主混音并编码为一个 AAC 音轨。仅系统声、仅麦、双开均受支持。
- 输入设备列表来自 OBS `win-wasapi` 的实时属性；设备 id 不在当前列表时拒绝 start。
  Windows 设置中的“麦克风隐私”必须允许桌面应用访问麦克风。
- 窗口列表和 start 均使用 OBS `window_capture` 的同一属性值，避免把任意句柄送入
  libobs。当前使用 WGC、捕获客户区并包含光标。
- OBS 的窗口匹配值基于标题、类名和可执行文件。窗口关闭或最小化后可能输出黑帧；
  session/WebUI 会持续显示此警告，用户应停止并重新选择。本批不声称自动换窗。
- 区域、游戏、纯音频与摄像头仍禁用。

## 回归

```powershell
# 全屏 x264/硬编 + 全屏双音源；无输入设备会明确 skip
powershell -ExecutionPolicy Bypass -File .\scripts\record-regression.ps1

# 额外录制标题包含 Chrome 的窗口
powershell -ExecutionPolicy Bypass -File .\scripts\record-regression.ps1 `
  -WindowTitleSubstring Chrome
```

每个 case 都执行原有文件大小、视频/音频流、分辨率与媒体/墙钟时长门槛。脚本能确认
麦克风源已进入混音路径，但自动化无法判断人声内容；发布验收仍需对只麦和双开样片
进行一次人工试听。
