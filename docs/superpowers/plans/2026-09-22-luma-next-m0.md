# Luma Next M0 Implementation Plan

> **For agentic workers:** Implement task-by-task. Steps use checkbox syntax.

**Goal:** Scaffold the luma-next Rust workspace and ship a minimal HTTP control plane so GET /api/v1 and GET /api/v1/session work via curl (M0 acceptance).

**Architecture:** Single Cargo workspace with binary crate luma-engine. Axum serves JSON matching the old Luma probe/session shape. No libobs link in M0 — only placeholders and clear TODOs for M1.

**Tech Stack:** Rust stable, Cargo workspace, axum + tokio + serde_json, clap for bind address/port.

## Global Constraints

- Product: Luma Next; GPL note in README (libobs comes in M1+)
- Windows-first; do not require OBS binaries to build/run M0
- Default bind 127.0.0.1; port 18765 (same as old Luma LAN) unless conflict — document the port
- JSON envelope like old Luma: { "ok": true, "data": ..., "error": null }
- Do not port C# MF code; do not embed libobs yet
- Keep existing docs: README.md, docs/BOUNDARY.md, docs/CADENCE.md (include them in the new repo)
