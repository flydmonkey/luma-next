# M7：原生区域框选与游戏捕获

M7 把区域模式的默认交互从浏览器显示器地图改成 Windows 桌面覆盖层，并新增真实的
OBS `game_capture` 路径。两者仍复用同一 session、音频混音、暂停、热键与 stop 校验。

## 原生区域框选

`POST /api/v1/region/pick` 可带 `{"display_id":"..."}`。引擎在所选显示器上创建
Per-Monitor-V2 DPI aware 的顶层半透明 Win32 窗口；按下鼠标并拖拽，松开即确认，Esc
取消。最小尺寸 32×32，宽高按编码要求对齐为偶数。成功才持久化 `capture_mode=region`、
`display_id` 与虚拟桌面物理坐标；取消不会改设置。覆盖层一次只覆盖所选显示器，跨屏
矩形仍按 M6 规则拒绝。

浏览器地图保留为明确标注的回退。在 `--no-tray`、无人值守或没有交互桌面的环境中，
可直接向 start 提交数字 `region`，不要调用 picker。125%/150% 缩放由线程级
Per-Monitor-V2 坐标处理；混合 DPI 显示器热插拔后应刷新 targets 再框选。

## 游戏捕获

`GET /api/v1/targets` 的 `games` 来自 OBS `game_capture` 的 `window` 属性列表；列表项只是
hook 候选，不代表一定可捕获。settings/start 接受 `capture_mode=game` 与 `game_id`，且
id 必须来自当前枚举。引擎创建真实 `game_capture` 源，使用 window 模式、普通 hook
频率并关闭 anti-cheat hook；绝不回退成 `window_capture` 冒充成功。

start 最多等待 6 秒取得非零画面尺寸。超时会停止并返回明确错误。Luma 与目标程序应以
相同权限运行，目标应使用 DirectX/OpenGL/Vulkan；受保护内容、反作弊游戏、权限不一致、
多 GPU 或不支持的渲染 API 可能无法 hook。系统声、麦克风、暂停/恢复和热键沿用现有路径。

```powershell
curl http://127.0.0.1:18765/api/v1/targets
curl -Method Post http://127.0.0.1:18765/api/v1/region/pick `
  -ContentType application/json -Body '{"display_id":"monitor-0"}'

# CI 仍使用数字矩形；指定真实游戏标题才强制跑 game_capture
powershell -ExecutionPolicy Bypass -File .\scripts\record-regression.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\record-regression.ps1 -GameTitleSubstring "My Game"
```

默认回归把区域录制与暂停合并，并检查 640×360 分辨率、媒体钟冻结和 ffprobe 时长。
未传 `-GameTitleSubstring` 时会明确打印 game SKIP；传入后，枚举不到或 hook 失败均使脚本
非零退出。

## 本机验证记录（2026-09-22）

- 原生覆盖层在 1920×1080、100% 缩放显示器实际弹出；遮罩、提示与取消路径可见。
- OBS 枚举出游戏候选，但本机没有可验证的 DirectX/OpenGL/Vulkan 游戏。对 ChatGPT 与旧
  Luma 普通窗口的真实 `game_capture` 尝试均在 6 秒后诚实失败，未回退窗口捕获。
- 游戏硬案例因此记录为 SKIP；必须在有兼容 3D 目标的机器上用上述参数补跑。
