# M1：libobs 全屏与系统音频录制

状态：已在本机 OBS RelWithDebInfo 构建上完成闭环验收。

## 实现决策

- `luma-engine` 进程内直接链接 `obs.dll`，用一个窄 C ABI 桥接官方 `obs.h`；没有
  obs-websocket 或 `obs64.exe` 子进程。
- 初始化顺序为 `obs_startup`、libobs data path、video/audio reset、精确加载
  `win-capture`、`win-wasapi`、`obs-x264`、`obs-ffmpeg`、`obs_post_load_modules`。
- 主显示器使用 WGC。此机的 AMD 驱动对 DXGI `DuplicateOutput1` 返回
  `DXGI_ERROR_UNSUPPORTED`，因此不把失败重试留在默认自动选择里。
- 当前输出为 30fps、最大 1920×1080、x264 6000kbps、AAC 160kbps、MKV。

## 构建路径

缺省路径：

```text
source: C:\Users\Administrator\Projects\obs-studio
rundir: C:\Users\Administrator\Projects\obs-studio\build_x64\rundir\RelWithDebInfo
```

可在编译前设置 `LUMA_OBS_SOURCE`、`LUMA_OBS_RUNDIR` 覆盖。构建脚本只编译很薄的
桥接文件，并复制已有 rundir DLL/FFmpeg mux helper 到 Cargo 输出目录；不会重编 OBS。

## 验收

```powershell
cargo run -p luma-engine

curl.exe -X POST http://127.0.0.1:18765/api/v1/session/start
Start-Sleep -Seconds 15
curl.exe http://127.0.0.1:18765/api/v1/session
curl.exe -X POST http://127.0.0.1:18765/api/v1/session/stop
```

stop 内部运行等价于：

```powershell
ffprobe.exe -v error `
  -show_entries stream=codec_type:format=duration `
  -of json $outputPath
```

只有文件非空、编码帧大于零、同时存在视频/音频流，且媒体时长与墙钟时长在允许误差
内，API 才返回成功。失败原因会进入 session `error`，不静默伪装为完成。
