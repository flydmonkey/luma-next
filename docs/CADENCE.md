# Luma Next — 开发节奏与里程碑

> 定稿：采用 **第一版** 里程碑顺序（2026-09-22）。  
> 曾讨论过「引擎优先」重排，最终仍用本版：先 HTTP 契约占位，再真录制，再 WebUI。

## 原则

1. **学了再改**：动 libobs 采集/编码前，对照 OBS / libobs-rs 既有做法，写短笔记，禁止闭门试错硬编路径。
2. **小步可测**：每个里程碑有手测门槛；不达门槛不宣称完成。
3. **双场景回归**（一旦有真录制）：静止桌面 + Chrome 播放动态视频；禁止短视频（音长视短）。
4. **旧仓只读**：../record 可查教训与 API 习惯，禁止移植 MF/GpuSurfaceWriter 代码。
5. **改边界先改文档**：范围变化先更新 BOUNDARY.md，再写代码。
6. **时间口径可追溯**：UI 使用 OBS 媒体时间；墙钟仅用于交叉校验，媒体、墙钟与
   ffprobe 的偏差必须由回归脚本显式断言。

## 里程碑（第一版）

| 里程碑 | 目标 | 手测门槛 |
|---|---|---|
| **M0（完成）** | HTTP 起服 + /api/v1 probe/session 占位 | curl 探活与 session 查询通 |
| **M1（完成）** | libobs 全屏 + 系统声录到文件 | ffprobe：音视频时长接近墙钟；硬案例不成短视频 |
| **M2（完成）** | 正式 WebUI 对接 start/stop/状态，并迁移旧版核心信息架构 | 页面可完整开始/停止，未实现能力明确禁用 |
| **M3（完成）** | library 安全列表/删除、settings 持久化、20 秒回归脚本 | 测试覆盖路径逃逸；回归同时验证音视频流与时长 |
| **M4（完成）** | libobs 枚举 H.264 编码器、持久化选择、start 内诚实降级 | x264 与本机 AMF 均过 20 秒门槛；失败原因进入 session |
| **M5（完成）** | WASAPI 麦克风混音与 OBS WGC 窗口捕获 | 系统声/麦/双开与窗口成片通过 ffprobe；无效目标明确拒绝 |
| **M6（完成）** | 区域、多显示器、OBS 暂停与 Windows 全局热键 | 区域分辨率、暂停媒体钟、多屏或明确 skip；热键与托盘共用 session |
| **M7（完成）** | 原生桌面区域覆盖层与真实 OBS game_capture | picker 物理坐标/DPI；兼容游戏成片或明确 hook 失败/skip，禁止 window 冒充 |

## 日常流程

1. 开任务 → 对照当前里程碑验收标准  
2. 引擎相关 → 先读 OBS/libobs-rs 再改  
3. 本地手测双场景（M1 起）  
4. 更新遥测/文档若行为变化  
5. 提交说明写清：做了什么、如何手测、未做的边界

## 明确不抢跑

- 托盘只是同进程入口，必须复用 HTTP 控制面相同的 session/录制实现；无 UI 回归使用
  `--no-tray`。
- 主宿主默认单实例；自动启动属于当前用户登录会话，不演变为 Windows Service。
- 用户发布验收必须从 `scripts/pack.ps1` 生成的旁路 OBS 运行时安装目录启动；源码树
  `cargo run` 仅用于开发与无托盘回归。
- M2 前不把 WebUI 美观/动效当主任务
- M4 前不承诺「全厂商同级调优」——以 OBS 后端能选能录 + 诚实失败为准
