# Luma Next — 开发节奏与里程碑

> 定稿：采用 **第一版** 里程碑顺序（2026-09-22）。  
> 曾讨论过「引擎优先」重排，最终仍用本版：先 HTTP 契约占位，再真录制，再 WebUI。

## 原则

1. **学了再改**：动 libobs 采集/编码前，对照 OBS / libobs-rs 既有做法，写短笔记，禁止闭门试错硬编路径。
2. **小步可测**：每个里程碑有手测门槛；不达门槛不宣称完成。
3. **双场景回归**（一旦有真录制）：静止桌面 + Chrome 播放动态视频；禁止短视频（音长视短）。
4. **旧仓只读**：../record 可查教训与 API 习惯，禁止移植 MF/GpuSurfaceWriter 代码。
5. **改边界先改文档**：范围变化先更新 BOUNDARY.md，再写代码。

## 里程碑（第一版）

| 里程碑 | 目标 | 手测门槛 |
|---|---|---|
| **M0** | HTTP 起服 + /api/v1 probe/session 占位 | curl 探活与 session 查询通 |
| **M1** | libobs 全屏 + 系统声录到文件 | ffprobe：音视频时长接近墙钟；硬案例不成短视频 |
| **M2** | WebUI 对接 start/stop/状态 | 页面可完整开始/停止一段录制 |
| **M3** | library 列表/删除、settings 持久化 | 与旧 Luma 使用习惯接近 |
| **M4** | 硬编选择 + 诚实降级/遥测 | 可选 AMF/QSV/NVENC/x264；失败明文；遥测不含假 30fps |

## 日常流程

1. 开任务 → 对照当前里程碑验收标准  
2. 引擎相关 → 先读 OBS/libobs-rs 再改  
3. 本地手测双场景（M1 起）  
4. 更新遥测/文档若行为变化  
5. 提交说明写清：做了什么、如何手测、未做的边界

## 明确不抢跑

- M0/M1 完成前不上桌面薄壳（Tauri 等）
- M2 前不把 WebUI 美观/动效当主任务
- M4 前不承诺「全厂商同级调优」——以 OBS 后端能选能录 + 诚实失败为准
